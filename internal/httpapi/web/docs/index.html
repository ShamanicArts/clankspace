02 · the idea

The product lives in the agent loop.

The website is only a quiet window for people, projects, keys, replicas, and corrections. Agents do the everyday checking and checkpointing from their normal harness.

Accrued intent
What collaborators meant and why, collected over time.
Checkpoint
A short durable implication, not a transcript or status update.
Trajectory
Work currently in motion: objective, rationale, paths, branch, and agent run.
Conflict
Two approaches that cannot safely coexist—not merely two edits near each other.

Brainstorms, routine edits, and obvious implementation detail do not need records.

Pause only for a real choice.

Surface incompatible direction before editing. Absorb compatible context silently.

Paraphrase professionally.

What the campaign proved
  1. Hosted owner registration and one-time email sign-in.
  2. Invite acceptance and one account across several workspaces.
  3. Project-scoped agent identity.
  4. Local pairing and context retrieval while cloud was offline.
  5. Reconciliation after cloud returned.
  6. Independent self-host authority with an optional cloud mirror.
  7. Signed bundle import into a third peer.
  8. Revocation blocking a later peer write.

      


      

        09 · trust boundary
Useful for trusted collaborators. Honest about what it is not.

        
Protected now
  • Project-scoped, revocable agent keys
  • HTTP-only browser sessions and CSRF checks
  • One-time expiring email and invitation links
  • Signed, chained, bounded replica events
  • Encrypted installation and replica secrets at rest
  • Migration backups and downgrade refusal
Later hardening
  • Public registration and billing
  • Private-repository OAuth
  • Hosted-content end-to-end encryption
  • Account recovery operations
  • Transitive federation
  • Large internet-scale replication soak tests
